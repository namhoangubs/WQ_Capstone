RUNNING THE LATER PHASE ONLY
============================

Purpose
-------
This run uses an existing Phase 1 handoff to train rolling state-specific
WGANs, simulate portfolio returns, calculate VaR and ES/CVaR, and compare the
fixed transition model with exactly one dynamic transition model. It does not
rerun HMM calibration or dynamic-model selection.

Prerequisites
-------------
1. Open PowerShell or Anaconda Prompt in the repository root.
2. Activate an environment containing Python, TensorFlow/Keras, pandas, numpy,
   scipy, scikit-learn, statsmodels, hmmlearn, joblib, and matplotlib.
3. Confirm that the Phase 1 registry exists:

   phase_1/selected_models_for_later_phases_q4.csv

4. Confirm that the registry points to existing files under:

   phase_1/production_q4/

The registry must contain exactly one baseline row with model_id
fixed_hmm_transition and exactly one dynamic row. The dynamic row determines
which dynamic model is compared with fixed transition.

Using the existing Group-Weighted MLG handoff
-----------------------------------------------
The clean deployment branch already contains a registry for:

    group_weighted_multinomial_logistic_gam

If that is the intended dynamic model, do not edit
phase_1_model_specifications.csv. It is not read for model selection during a
later-phase-only run.

Using a different dynamic model
-------------------------------
The dynamic model used by a later-phase-only run is determined by the
dynamic row in:

    phase_1/selected_models_for_later_phases_q4.csv

The supported model_id values are:

    dynamic_duration_logit
    pvalue_vif_selected_mlr
    multinomial_logistic_gam
    group_weighted_multinomial_logistic_gam
    state_interaction_multinomial_logistic_gam

For example, to run Original Regularized MLG, the dynamic row must have:

    model_id=multinomial_logistic_gam
    model_family=multinomial_logistic_gam

Its artifact fields must point to the matching Original MLG files, for
example:

    fitted_model_artifact=phase_1/production_q4/multinomial_logistic_gam_production_q4.joblib
    coefficient_file=phase_1/production_q4/multinomial_logistic_gam_coefficients_q4.csv
    preprocessing_file=phase_1/production_q4/multinomial_logistic_gam_preprocessing_q4.json
    spline_artifact=phase_1/production_q4/multinomial_logistic_gam_spline_q4.joblib

The shared HMM, fixed-transition matrix, production stock returns, and
transition_probability_file must also be present. The transition probability
file must have been generated by the chosen model and contain its daily
DYNAMIC_P_TO_0 through DYNAMIC_P_TO_3 columns.

Do not change only model_id. Every model-specific artifact and the daily
dynamic probabilities must belong to the same model and Phase 1 refit.

If the desired artifact bundle does not already exist, return to
phase_1_model_specifications.csv, keep fixed_hmm_transition enabled, enable
only the desired dynamic model, and run Phase 1. That run will generate the
correct registry and artifacts. Then rerun this later phase with
run_scope=later_phases.

Configuration
-------------
Open pipeline_config.json and set:

    "run_scope": "later_phases"

Keep the selected-model registry path as:

    "selected_model_registry":
        "phase_1/selected_models_for_later_phases_q4.csv"

The default experiment uses 10 independent portfolios of 50 stocks, equal
weights, 10,000 simulation paths per forecast date, WGAN warm-up through 2016,
and risk forecasts beginning on 2017-01-03.

Dry run
-------

    C:\Users\namho\anaconda3\python.exe run_pipeline.py --config pipeline_config.json --dry-run

The dry run validates the registry and reports the dynamic model without
training WGANs or running simulations.

Execute the later phase
-----------------------

    C:\Users\namho\anaconda3\python.exe run_pipeline.py --config pipeline_config.json

Main outputs
------------
Per-portfolio outputs are written under:

    run_outputs/portfolio_01/
    run_outputs/portfolio_02/
    ...

Important files include:

    wgan_loss_report.csv
    daily_risk_forecasts.csv
    risk_scores.csv
    rolling_250_day_exceedances.csv
    simulated_state_counts.csv
    portfolio_real_returns.csv
    wgan_checkpoints/

The aggregate comparison is written under:

    run_outputs/aggregate_comparison/

Important aggregate files include:

    all_portfolio_risk_scores.csv
    paired_portfolio_scores.csv
    primary_scorecard_summary.csv
    backtest_p_value_summary.csv

The run summary is:

    run_outputs/run_summary.json

Running a different dynamic model
----------------------------------
The later phase consumes the registry, not the model-specification CSV. To
run Original Regularized MLG, the registry must point to a complete Original
MLG production artifact bundle and to a transition-probability file whose
DYNAMIC_P_TO_* columns were generated by Original MLG.
